## ⚡ 两个硬性特性

### 1. 完全热更新，不重启手机

- **装新版本**：管理器把文件放到 `modules_update/`，模块的 `hotupdate.sh`
  守护会在 **8 秒内**自动检测、同步、重启服务 —— **不用重启手机**
- **改游戏名单**：WebUI 里增删，**3 秒内自动生效**，连刷新都不用

实测：模拟安装新版本后 9 秒完成全部切换。

### 2. 游戏名单全部在 WebUI 里管理

不用碰任何配置文件。

## 核心思路

市面上大多数"优化模块"做的是**降频省电**：砍 CPU 上限、关加速机制。
代价是卡顿——点开 App 要等、滑动掉帧。

**MiTuner 走的是另一条路：不碰性能上限，只减少浪费。**

| 做法 | 效果 |
|---|---|
| 降低 `swappiness` | 少把活跃内存挤进 zram，App 切回来不用重新解压（**这是"点开微信卡1-2秒"的元凶**）|
| 保留文件缓存 | App 启动时大量 `stat`/`open` 命中缓存，**冷启动更快** |
| 优化 IO 预读 | 减少无效预读，加快资源加载 |
| 提高调度响应 | `schedutil` 升降频更快，减少"点了没反应" |
| 按场景差异化 | 游戏时进一步放开，息屏时收紧省电 |

**性能上限完全不动** —— CPU 频率、温控策略都交给系统和你的原有调度模块。

## 三态调度

| 档位 | 触发条件 | swappiness | vfs | read_ahead | rate_limit |
|---|---|---|---|---|---|
| 🎮 **GAME** | 前台在游戏白名单 | **40** | **60** | **512KB** | **200µs** |
| 💡 **NORMAL** | 亮屏非游戏 | 60 | 80 | 256KB | 500µs |
| 🔋 **IDLE** | 屏幕熄灭 | 80 | 120 | 128KB | 2000µs |

息屏时还会降低 CPU 下限（c0=220M / c1=400M / c2=1200M）省电。

> 检测间隔：亮屏 3 秒 / 息屏 5 秒。从 IDLE 醒来**立即切换**，无延迟。

## WebUI 游戏白名单管理

管理器里点开模块即可，三个标签页：

### 📋 名单

- 查看全部游戏（中文名 + 包名）
- **搜索**（按游戏名或包名）
- **单个删除**（点右侧 ×）
- **↺ 恢复内置名单**（一键还原 109 款）
- 当前正在运行的游戏会**高亮标红**

### 📱 已装应用

- 点「扫描」列出手机上所有第三方应用
- 点选多个 → 「添加选中」批量加入
- 支持搜索、全选、清空
- 已在名单里的应用不会重复显示

### ✏️ 手动添加

- 填包名 + 备注名（可选）
- 适合添加还没安装的游戏

> 包名怎么查：打开游戏，看 WebUI 顶部「前台应用」那一行就是。

**所有操作立即生效**（3 秒内），无需重启、无需刷新。

## 安装

### 要求

- Android 13+
- Root：**APatch / KernelSU / Magisk** 任一

### 首次安装

1. 从 [Releases](../../releases) 下载 `MiTuner.zip`
2. 在 Root 管理器里安装
3. **重启一次**（首次安装需要，之后更新都不用）

### 后续更新

直接装新版本 zip 即可，**模块会自动热应用，不用重启**。

## 配置

一般不需要动，全部可在 WebUI 完成。

`/data/adb/mituner/settings.conf`（改完重启守护生效）：

```sh
# GPU 自动识别（白名单没命中时）：1=开 0=关（默认关）
# 注意：会自动识别可能误判（渲染重的非游戏应用），建议保持 0
AUTO_GAME=0
AUTO_GPU_TH=60

# 息屏时 CPU 下限
IDLE_MIN_C0=220000
IDLE_MIN_C1=400000
IDLE_MIN_C2=1200000

# IO 预读（KB）
NORMAL_RA=256
GAME_RA=512
IDLE_RA=128
```

`/data/adb/mituner/games.conf`（建议用 WebUI 改）：

```sh
# 一行一个包名，可带备注
com.example.game            # 我的游戏
com.another.game	另一个游戏
```

## 不做什么（重要）

为了和你的其他调度模块共存，MiTuner **明确不碰**这些：

| 不碰的东西 | 原因 |
|---|---|
| ❌ `scaling_max_freq`（CPU 频率上限） | 那是 CTS 等调度模块的职责 |
| ❌ `scaling_governor` | 同上 |
| ❌ 温控配置 `thermal-*.conf` | MIUI 加密，且改了有风险 |
| ❌ 被其他模块 `chattr +i` 锁的文件 | 改了会冲突 |

**只改内核暴露的可调参数**，全部可逆，卸载即恢复。

## 排查

### 看日志
```bash
tail -f /data/local/tmp/mituner.log
```

### 看状态
```bash
cat /data/adb/mituner/state        # 当前档位
cat /data/adb/mituner/fb_flag      # 前台包名
wc -l /data/adb/mituner/games.list # 生效的游戏数
```

### 守护进程
```bash
cat /data/local/tmp/mituner.pid             # 调度守护
cat /data/local/tmp/mituner-hotupdate.pid   # 热更新守护
```

### 常见问题

**Q: 加了游戏但没生效？**

等 3-5 秒（service.sh 的检测间隔）。看日志有没有 `白名单重载: N 个`。

**Q: 装了新版本还要重启吗？**

不用。`hotupdate.sh` 会在 8 秒内自动同步。如果没生效：
WebUI 点「重启守护进程」手动触发。

**Q: 和 CTS 模块冲突吗？**

不冲突。MiTuner 不碰 CPU 频率上限和 governor。

**Q: 游戏里还是没感觉？**

先在 WebUI 确认「当前档位」是不是「游戏模式」。
如果不是，说明前台包名没匹配上，检查白名单。

## 卸载

Root 管理器里移除，或：

```bash
su -c 'rm -rf /data/adb/modules/mituner'
```

`uninstall.sh` 会从 `orig.conf` 还原**全部原始参数**，并停止所有守护进程。

## 技术细节

### 为什么 `swappiness=100` 会导致卡顿

Android 用 zram 把不活跃内存压缩存放。`swappiness=100` 意味着
**哪怕内存还很充裕，系统也很积极地往 zram 挤**。

App 被换出后，切回前台时要解压 —— 这就是"点开微信要等 1-2 秒"。

实测本机 15GB 内存，`MemAvailable` 常年 6-7GB，完全不需要这么激进。

### 热更新的实现

```
管理器安装新版本
    ↓
写入 /data/adb/modules_update/mituner/
    ↓
hotupdate.sh（每 8 秒检查）
    ↓ 检测到目录
备份旧版 → 全量同步新文件 → 设权限 → 清 update 标记
    ↓
sh apply.sh（重新应用优化）
    ↓
重启 service.sh（kill 旧 pid → setsid 启动新的）
    ↓
✅ 已生效，无需重启手机
```

### 白名单匹配

清洗成纯列表 + `grep -Fx` 整行精确匹配：
- 无正则编译开销
- 不误匹配（`com.a.game` 不会命中 `com.a.game2`）
- 特殊字符无风险

删除时用 `grep -vE "^包名([[:space:]]|$)"`，兼容 `包名\t备注`。

### 为什么默认关闭 GPU 自动识别

实测 AI 应用 `me.rerere.rikkahub` 渲染时 GPU 到 96%，
被自动识别误判为游戏，切了 GAME 档。

对于"只要 3A 游戏"的场景，**白名单更精准可控**。
